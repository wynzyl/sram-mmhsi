00

Overview

What the system is for, who is holding the mouse, and where the colour goes.

The job. Three staff roles spend their whole shift in this product. A registrar opens it to find one student among thousands and correct a field. A cashier opens it to post a payment against an assessment and hand back a receipt. An admin opens it to see which records are stuck. Nobody is browsing. Every screen is a search, a form, or a table — and the interface's job is to make the record legible and the next action obvious.

The look. Warm neutral surfaces, hairline rules, records set in tabular figures, and a primary action in solid ink rather than colour. Red is the identity — a single bright vermilion that marks the brand, the active module, and things that are genuinely wrong. Nothing else is coloured.

Why ink, not red, for the primary button. A red accent in a records system tends to spread: red buttons, red delete icons, red required markers, red overdue balances, red validation, red active tabs. By the time a registrar sees it all at once, red has stopped meaning anything. So the primary action takes ink (near-black in light, near-white in dark) and red is held back for alarm and identity. §04 is the enforceable version of that rule.

01

Principles

Four tests that settle an argument without a meeting.

The record is the interface

Names, IDs, terms and amounts are the content. Chrome shrinks before content does, and a record is never truncated where the truncation could be mistaken for the value.

Red is a warning, not a colour

If red appears twice on a screen for two different reasons, one of them is wrong. Ink carries emphasis; red carries alarm.

Name every action

Row actions are words. An icon-only pencil or trash in a roster costs a registrar a guess on every row and is a compliance risk on destructive paths.

Both themes ship together

Dark is not a skin applied later. A component is not done until it has been read in both themes at AA, including its charts and its empty state.

02

Two themes

One token layer, two value sets. Use the toggle at the top of this page — every specimen below is live in both.

  • Semantic names only. Components reference --surface, --text-muted, --bad. A component that names a hex or a ramp step (chalk-200) will break in one of the two themes.
  • Dark is not inverted. Light goes canvas → white cards. Dark goes near-black canvas → lighter cards. Lightness rises with elevation; it does not flip.
  • Dark drops shadow, uses surface. Shadows are nearly invisible on #131211. Separate layers with a lighter surface plus a 1 px border instead.
  • Never pure black or pure white. Canvas bottoms out at #131211 and tops out at #F8F7F5. Full-contrast pairs cause halation on long table sessions.
  • Chromatic values change per theme. Vermilion text goes from #C9241C to #FF6B60; success from #16794D to #54C08A. Same meaning, re-tuned for the background.
  • Follow the OS on first load, then let the user override, and persist the choice per user, not per device.
  • One copy deck. No theme-specific wording, no "dark mode" easter eggs, no illustration that only works on one background.

The red budget

A single bright accent only works if its licence is written down. This is the licence. It is the section to cite in review.

Red is allowed here

Active module indicator2 px bar on the selected item in the module rail — one per screenred-mark
Focus ringKeyboard focus, every theme, never removedred-mark / #FF6B60

Chart series 1Only when the series is the alarming one; otherwise start at series 2viz-1

Red is forbidden here

  • Primary buttons. Save, Enroll, Post payment, Submit — all ink.
  • Row action icons. A red trash icon on every roster row spends the whole budget before the registrar has done anything.
  • Column headers, tabs, breadcrumbs, table rules, links in body copy.
  • Ordinary debits and fees. A tuition line that is simply unpaid is hold, not bad. Red starts at the due date.
  • Empty states, onboarding, illustrations, section dividers, icons that mean nothing.
  • Two red things at once. If a form has an error banner, the focus ring is the only other red element permitted on that view.
Don't
Red "Delete", red trash icons, red required stars, red active tab, red overdue column — all on one roster.

Five meanings, one colour. The registrar now scans past all of them, including the one that mattered.

Do
Ink "Save changes". Named row actions in ink. Red only on the overdue amount and the focus ring.

Two red pixels on the screen, both of them load-bearing.

07

Voice & copy

Plain, exact, accountable. The product speaks like a competent registrar: it tells you what happened to the record and who it was logged against.

  • Sentence case everywhere, including buttons and column headers.
  • Name the action, not the mechanism: Enroll student, not Submit enrollment request.
  • A verb keeps its name through the flow: Post payment → posting → Payment posted.
  • Say what the system will do to the record, and whether it can be undone.
  • Errors name the field, the rule, and the fix. They do not apologise.
  • Never blame the student or the staff member. The subject of the sentence is the record.

Rewrites

Don't
Error: invalid input.

Which field, which rule, what now?

Do
Student number must be 10 digits in the form 2026-00184. This one has 9.

Field, rule, and the exact defect.

Don't
Are you sure you want to delete this?

No object, no consequence, no scope.

Do
Drop Juan M. Dela Cruz from ENG-101? Their grade record for this term is removed and the slot returns to the section. This is logged and cannot be undone here.

Names the person, the scope, the side effect, and the audit.

Don't
No records found!

Dead end with an exclamation mark.

Do
No students match "dela cruz" in 1st Sem 2026–2027. Try another term or clear the filters.

Repeats the query, names the filter that is probably to blame.

Discipline

  • Vertical rhythm between blocks is 48 px; between sections 64 px. Do not tune it per screen.
  • Prefer a hairline or a gap over a border; prefer a gap over a hairline. Nested cards are not allowed.
  • One primary action per view, bottom-right of the form's action bar, with the cancel to its left.
  • Every table screen owns its filter bar: search, term, and status — in that order, on every module.
  • A dense table earns its density by having quiet chrome around it. Do not crowd a compact table with tinted cells and badges in every column.

Colour-blind check

Red and green sit side by side in every payment table, which is precisely the pair that fails for the most common form of colour blindness. The badge word is what carries the meaning; the colour only speeds up a reader who can see it. Screenshot any payment or grade screen, desaturate it, and confirm every state is still identifiable — in both themes.

Theme switching

// 1. Follow the OS, then let the account override.
const saved = user.preferences.theme;               // 'light' | 'dark' | null
const osDark = matchMedia('(prefers-color-scheme: dark)').matches;
document.documentElement.dataset.theme = saved ?? (osDark ? 'dark' : 'light');

// 2. Set it before first paint to avoid a flash of the wrong theme.
// 3. Persist on the account, not the device — staff share workstations.
// 4. Never read a hex in a component. Read a token.

.balance--overdue { color: #C9241C; }             // breaks in dark

Don'ts

Use this list to audit an existing screen. Most of the findings in a records portal are on it.

  • No red primary buttons. Ink carries emphasis; red carries alarm. Pick one meaning per colour and this is it.
  • No icon-only row actions. A pencil, an eye and a trash in a 12-column roster is three guesses per row and no audit trail in the UI.
  • No red for ordinary unpaid balances. Unpaid is hold until the due date passes.
  • No inverted dark theme. Cards get lighter than the canvas, not darker, and pure black is never the canvas.
  • No hardcoded hex in a component. If a value is not a token, one theme is already broken.
  • No proportional figures. Non-tabular digits make a balance column visibly wobble.
  • No blank cell for a missing grade. An em dash plus a badge; blank reads as a bug or a zero.
  • No truncated identifiers. A student number cut mid-string is a wrong number.
  • No status conveyed by colour alone, anywhere, in either theme.
  • No mascots or illustrations in empty states. A sentence naming the active filter and one action.
  • No more than two type weights or three hues per screen. Count them before you ship.

  • Red audited: every red element on the screen appears in the §04 allow-list.
  • Greyscale test passed — no meaning lost.
  • Exactly one primary action visible, in ink.
  • Every row action has a word.
  • Empty, loading, error, long-name and no-permission states designed, not improvised.
  • Keyboard-only pass completed, focus ring visible at every stop in both themes.
  • All figures tabular; identifiers in mono; nothing truncated that identifies a person.
